# V4：原方法上的新增步骤与源码接入推导

日期：2026-10-21。本文是设计约束与待验证接口，不是已选定的新模型，也不是完整系统实现报告。默认网络仍只有作者 E/D；公共输出头、差值分解、分解网络、重组网络均未启用。

## 1. 从作者实际计算图出发

固定作者版本 `5dc2a0f7c6b692ca7914941745bd29b227ff4dbb`。

作者 `main.py:47–48` 的完整模型连接是：

`X → encode(X, 1) → g* → decode(g*, 3) → X_hat`。

`model.py:177` 把编码器末端特征映射为一个通道，tanh 输出范围为 [-1,1]。`model.py:182–198` 的解码器只接收这一张图，没有接收 RGB、编码器内部跳接或额外颜色码。因此原方法已经完成“把颜色恢复信息编码进灰度图”的任务，但没有把该信息显式拆成某个 Zc。`main.py:65` 的普通灰度仅是损失参照，不是可直接替换 g* 的解码输入。

区分三种对象：

- `g* = E_original(X)`：连续单通道训练输出。
- `U = Q8(g*)`：实际保存的 uint8 编码灰度，形状 H×W。
- `N(U) = U / 127.5 - 1`：接回原解码器的浮点输入。

原数字图像基线是 `X_base = D_original(N(U))`。精确恢复 U 只能保证回到这条基线；不能因此宣称 RGB 无损，因为作者 E/D 本身是近似恢复。

作者训练两阶段均直接使用连续 g*，第二阶段增加量化约束；数字收发后的目标属于我们新增的验证/训练职责，不能倒写成作者原有前向流程。

## 2. 最小改动的准确含义

首先保持原 E/D 拓扑、单通道瓶颈、数值接口和原目标的可复现定义。新增功能集中在编码输出与解码输入之间；只有实际可行性证据表明输出侧需要局部可学习改动时，才登记具体层及参数变化。

这里的“分解”是需要定义的数字表示操作，不预设为一个网络。其职责是构造可公开的基底 G0，以及对恢复 U 必需的私有对象 Zc。Zc 可以包含恢复所需的混合信息；没有证据时不能叫它“纯颜色”“身份通道”，更不能直接取原特征的几个通道就声称完成分离。

用 `P`、`J` 临时表示接口职责：

`P(U; public_profile) → (G0, Zc)`

`J(public_state, Zc; public_profile) → U_hat`。

这两个名字不对应新建的 nn.Module，也不意味着已经找到可行算法。若某候选还需要编码器末端特征 F，必须单独登记 P 的输入和来源；接收端不能访问 F。不能用这种符号省略来掩盖隐藏旁路。

对保持原数字基线的候选，首要关系是 `U_hat = U`。若后续研究改用近似重组，必须显式定义误差和最终 RGB 代价，建立单独版本，不能把它当精确接口的实现细节。

“参数改动小”不是充分条件：即使只增加一个输出头，若其私有码无法装进公开图、接收端缺少重组基底，或无钥匙已能恢复，仍不是可用方案。

## 3. 完整发送与接收关系

发送端按职责连接：

1. 原 E 生成 g*，按数字规则形成 U。
2. 待选定的保护操作形成 G0、Zc；外部记录独立序列化为 Zm。
3. 对 Zc/Zm 分别进行确定的序列化、必要压缩，再以 KC/KM 分别认证加密，得到 Cc/Cm。压缩在加密前；不是让网络学习密码算法。
4. 自适应写入器 W 根据 G0 与完整待传消息生成单通道 Gpub；实际量化保存，接收端重新读图。

接收端按职责连接：

1. 提取器 R 仅从接收的 Gpub 和公开配置提取消息及必要公开状态。
2. 消息按格式分流，分别认证解密、解码得到 Zc/Zm；认证失败则该路返回失败状态。
3. J 使用接收端确实能够取得的公开状态与 Zc 恢复 U_hat。
4. `N(U_hat)` 接入原 D，输出授权 RGB；Zm 独立还原外部记录。

W/R 是用户提出的新增自适应通信模块，其具体网络结构、嵌入位置与预算尚未选定；它们不替代原颜色 E/D。将通信提取器命名为 R，避免把它和原 RGB Decoder 混称为一个 Decoder。

KC 路径不依赖 KM 才能定位/提取 Cc，KM 路径也不依赖 KC；若消息格式做不到独立分流，就不满足当前双授权定义。公开配置、长度、必要定位信息以及它们的泄漏也属于设计的一部分，不能依赖发送端内存或未传输的掩码。密钥不写进公开配置。

本稿定义功能职责，不指定尚未验证的密码套件、纠错码或新网络层数。

## 4. 公共基底与容量：需要一起求解的接口

W 通常会改变 G0，所以不能默认 R 提取出 Zc 后就已经具备 J 所需的输入。候选必须明确采用以下哪一种依据：

- J 需要原 G0：通信模块须同时恢复它，相关辅助信息计入载荷；这是对该类候选的要求。
- J 使用从 Gpub 可确定计算的公开状态 A(Gpub)：编码和恢复公式必须证明该状态足够，不要求额外恢复 G0，但也不能在发送端偷偷使用不同状态。

目前两者均没有被选定为默认实现。特别是“Gpub + Zc”不能代替“G0 + Zc”，除非先证明写入变化已被正确处理。

在同一张 H×W 的 8bit 图中，公开视觉、医学信息、恢复私有数据与通信冗余共同消耗表示能力。每张图必须满足完整的实际比特预算：

`B_wire = B_Cc + B_Cm + B_header + B_recovery + B_channel ≤ B_verified_capacity`。

Cc/Cm 长度包括认证加密开销；恢复辅助信息若已放入密文，只计一次；B_channel 为所选通信方案实际需要的冗余，不预设一定采用纠错码。容量必须在相同画质、分辨率、接收条件与失败率标准下测量，不能用总像素位数冒充可用容量，也不能只数 Zc 张量维度。

码长超预算必须明确返回不可承载，不截断私有码、不偷偷用外部文件补全。若未来允许外部载荷，需要明确改变当前“同灰度载体”的系统定义。

公共输出头＋差值候选仍仅为一项候选：`Zc = U - G0`。511 种整数差值需要固定 9bit 表示，512² 时为 294912 bytes，尚未计任何协议开销；压缩后是否足够未知。新增头虽然仅 576 个权重，不能解决这个事实。也不能通过让 G0≈U、Zc≈0 获得看似优良的码率，却失去访问控制意义。

## 6. 原训练目标与已有监督怎样继承

独立原方法基线继续按作者源码定义恢复 MSE、VGG 灰度感知、TV、明度次序和量化项，保留源码与论文差异记录。不要把旧 V3 生成训练日程直接套到 V4。

在扩展模型中，必须分别记录下列职责，不能只保留原支路损失后宣称整个系统训练完成：

| 监督对象 | 作用 | 不能替代的证据 |
|---|---|---|
| D(N(U)) 与 X | 监测原单通道颜色表示的恢复能力，作为数字基线 | 不代表经过 W/R 后也能恢复 |
| 接收链末端 D(N(U_hat)) 与 X | 约束实际授权恢复 | 不使用发送端 Zc/G0 代替接收结果 |
| 实际 Gpub | 灰度外观、可用医学信息与公开暴露评价 | 只约束中间 G0 不够 |
| 所有公开可恢复状态 | 防止通过公开中间量绕过保护 | 只证明密文安全不够 |
| R 输出的比特与发送消息 | 通信正确性与认证成功率 | 低比特误码率不等于完整消息可解密 |

已训练 PanDerm／分离器／绑定医学头通过现有图像适配链接入：参数、统计量冻结，图像输入梯度保留。8500 主监督、7000 对照沿用既有资源选择。其训练期身份/医学表征目标必须与现有监督器的真实输出一一对应，不能凭空增加一个已经训练好的“像素匿名判别器”。现有医学六分类读出不是像素隐私证明。

真实加密、认证和硬比特判断不提供常规可微梯度。通信网络可先用与实际格式匹配的比特消息训练，并以真实密文闭环核验；这不等于已经实现跨密码操作的端到端反传。若需要更新保护操作或原 E 的表示，必须另行说明所采用的训练分段、代理目标及真实接收差距，不能默认把加密函数当恒等梯度。当前不擅自固定这些训练算法或权重。

所有选定的损失权重、载荷配置、优化器、日程和资源路径进入独立 configs；设备数不进入方法定义。未选定项仍为空，不用可执行默认值代替研究决定。

## 7. 下一项方法验证应回答什么

顺序按依赖推进，而非先堆网络：

1. 补齐并核验原 E/D 训练权重及原完整损失资源，获得真实 U 样本。随机初始化工程样本不能用于颜色承载/容量结论；作者预训练与同域基线应分别标记。
2. 针对拟采用的最小保护操作，写出确切 P/J 公式、整数范围、发送/接收输入和实际编码器；先做无新增可训练层的接口诊断。位平面/频域等分析只作为诊断，不因可分割就认定其中一部分是颜色或身份。
3. 同时测量实际码长、重组误差、无钥匙恢复与公开医学信息。先检验 `D(N(U_hat))` 是否回到原数字基线；公开 G0 若仍可由原 D 或重新训练的攻击者有效恢复，不能视为保护成立。
4. 只有候选明确了可恢复的数字对象，才设计 W/R 的负载接口与自适应写入，并核验真实接收、双路权限组合、错误密钥和损坏消息。需报告完整消息成功率，不只平均 BER。
5. 若需要局部输出侧学习，再登记该层、初始值、目标、参数增量和消融；比较原方法、仅保护、仅通信、完整扩展及监督的作用。不能先决定层再倒找理由。

上述方法样本实验尚未执行。当前已完成的是源码事实、接口约束和可行性判据的明确化；未选定分解算法、未增加生成网络、未启动训练。
