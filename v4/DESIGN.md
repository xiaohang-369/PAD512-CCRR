# V4设计：在Invertible Grayscale原方法与源码基础上增加授权与自适应传输

日期：2026-10-21。用户确认V4研究定位并授权新分支、下载源码、设计修改和服务器验证。用户另要求配置独立、设备/卡数可选。V4从V3建立独立工作树，但V3生成架构、旧训练日程不作为新方法默认值；已有监督器和证据只读复用。

最新决定：用户已同意试验“学习公开灰度＋加密恢复差值”。当前执行设计见[RESIDUAL_PLAN.md](RESIDUAL_PLAN.md)，明确原方法基线、原Encoder训练副本、冻结恢复参照、整数差值和真实PNG收发；不添加公共输出头或分解网络。[此前接口推导](INTERFACE_DESIGN.md)保留为设计依据，其中“差值路线未选定”的历史状态由本条取代。

用户进一步明确四阶段顺序：①原方法完整训练得G0；②加入监督训练得G1，验证身份下降和可接受医学代价；③Zc=G0−G1，加密并在监督下自适应嵌入得Gpub，再评价；④训练/完善自适应W/R，从Gpub恢复G1与Zc，重组G0后送原D0。当前优先阶段1，协议诊断只作历史工程记录。旧段落中G0指公共图的记号不再使用，历史候选不作为实施默认。

## 1. 已确定的研究定义

原主干为`X -> E_original -> 单通道编码灰度 -> D_original -> RGB`。颜色恢复信息必须在这个单通道表示中编码。我们的贡献是在原编码/解码之间及其必要接口上增加信息访问控制、双密钥、同灰度载体自适应嵌入/提取，并加入已训练监督机制。

不另外创造独立RGB私有编码器，不预先追加独立分解与重组网络，不把某个卷积通道称作天然颜色/身份通道，不把原普通灰度损失参照误作编码器输出。

必须保留：原E/D来源映射、数字灰度、外部记录Mp->Zm、KC/KM分别授权、自适应嵌入/提取、真实接收后恢复。原论文不提供显式Zc，这个接口须由局部改造的机制和载荷证据定义。

## 2. 本版已实现的修改

1. 完整固定作者源码和许可证，不修改上游文件。
2. E/D逐层迁移到现有PyTorch环境，无额外头、无第二RGB通路。原TF1.6不安装到共享环境。
3. 源码损失的数学算子、数字PNG接收和核权重HWIO/OIHW映射；完整VGG权重仍缺，不开放训练。
4. 配置驱动的CPU/多设备逐卡验证；真实PAD fit、A0及已训练监督器的可选只读验证。
5. 不执行optimizer，不生成训练checkpoint，不访问test图像，不更改已有模型。

本版是V4的原方法基础与验证入口，不是完整双授权系统。

## 3. 历史候选及已选方案的区别

用户现在选定的是学习灰度之间的整数差值，不是普通灰度与编码灰度相减，也不是低位颜色分解。第一版沿用原Encoder的训练副本生成公开图，原基线冻结；不采用下述额外输出头。下述候选和容量问题保留用于解释此前推导，实施以RESIDUAL_PLAN为准。

讨论过的最小参数改造是：原E末端共享64通道特征F，保留原灰度输出头h，增加同型公共头h_pub；先量化得到整数G*=Q8(h(F))与G0=Q8(h_pub(F))，定义Zc=G*-G0。接收时若能精确恢复G0、Zc，整数相加恢复G*再送入原D。仅新增一个64→1无bias 3×3输出层（576权重），没有新分解/重组网络。

但用户只确定了“原方法基础上增加步骤”，此前明确这个方案仍是候选，故本版默认网络不添加这个头。不能借创建V4就默默将它升级为已确认主架构。

候选存在实质可行性问题：
- 差值[-255,255]有511种值；512²的原始9bit差值为294912 bytes，超过同尺寸单通道总像素262144 bytes，更不等于可用写入预算。必须验证实际无损编码长度和含metadata/nonce/tag/header的完整容量。
- W改变G0后不能直接Gpub+Zc；若采用此候选，提取端必须能恢复公共基底，或编码端/嵌入端共同定义可由接收图确定恢复的基底。不能凭空交给新R网络解决。
- 若G0=G*、Zc=0，恢复/码率很好但授权无意义。必须在允许攻击者得到Gpub及任何可公开恢复G0的条件下评价无钥匙RGB恢复和关联。
- 解密授权对象的完整性不等于公开图匿名；灰度接近不等于没编码。

进入该候选实施前，先用已核验训练权重的冻结原E输出做数字对象/实际码长/基底恢复可行性实验，再固定接口与训练配置。当前随机初始化工程验证不具备这种方法证据。失败时记录失败，不擅自扩大网络、偷偷改成有损残差或忽略额外载荷。V4设计不预定码长、不假设颜色只在低位或高频。恢复原G0只是依赖该基底的候选要求，并非所有候选的共同前提；共同要求是接收端有足够的真实输入重组原解码器所需的单通道表示。

## 4. 已训练监督机制的接入

沿用已确定8500主监督、7000对照作为只读资源；PanDerm/分离器/绑定原医学头冻结参数和统计，生成图路径保留输入梯度。不是重新训练一套监督网络。

当前接口验证覆盖：实际fit首批16张RGB/普通灰度和已有A0同数值策略比对，再让原E/D随机输出经过监督器，检查对E/D的输入梯度、冻结参数不变。它仅证明接口连通，不证明生成图医学效用或像素隐私。

第二阶段监督对象为G1，第三/四阶段为实际Gpub，同时评价无需钥匙可恢复的G1及授权RGB；现有六分类医学读出不能替代实际身份识别评价。

用户已明确目标为身份识别能力降低、医学损失可接受，不以绝对匿名或医学零下降为前提。普通灰度另作为身份/医学对照；原方法、V4有/无监督共同构成比较组。完整恢复差值接口已选定，具体身份效果通过实际图像评价，不由工程CE梯度检查替代。

## 5. 训练设计与配置

配置全部独立在configs。第一阶段按作者源码训练定义准备，采用参考的256×256、90+30、Adam、全局batch8与原损失，不静默沿用旧V3的batch16或B/C1日程。后续阶段参数独立登记；硬件并行配置不改变全局batch定义。

训练入口按上述用户四阶段推进，不以压缩/收发检查取代研究主线。代码库当前没有V4训练入口；首项待落实的是原方法完整训练资源、配置和训练器。

GPU编号、卡数与物理机器路径不进入模型代码。未来DDP全局batch不随卡数自动增长；本版多卡功能是逐卡工程检查，DDP训练未实现。
