# V4 已选试验方案：学习公开灰度与加密恢复差值

2026-10-21，用户在完整讨论发送与接收流程后同意“设计好试试”。本方案取代此前未选定的保护接口表述；选择的是数字差值收发路线，不是原论文已有的分解机制。新增公共头仍不是默认结构。

**最新顺序纠正：严格按用户四阶段推进。原方法训练 → 加监督验证G1 → 对差值加密并在监督下自适应嵌入、评价Gpub → 完整提取恢复训练与验证。不得以压缩或协议诊断作为主线，更不能将其通过记作前两阶段完成。当前下一项工作是第一阶段。**

统一命名：G0为原论文基线生成的编码灰度；G1为加入监督后生成的编码灰度；Zc=G0−G1；Gpub为嵌入后的实际发布图；D0为第一阶段保留的原Decoder。此前文档中G0曾指公开基底的用法停止使用。下文U_ref/U_public/U_tx在数字实现中分别对应G0/G1/Gpub。

## 1. 图像与原方法的关系

先在同一数据协议下训练原作者 E/D。保留其多尺度主干、残差块、单通道输出层及原 Decoder；保留源码目标与两阶段联合训练定义。源码/论文差异沿用 SOURCE_MAP 记录，数据、分辨率适配单独登记，不宣称逐字复现论文实验设置。

将选定基线 E_ref、D_ref 作为只读恢复参照。U_ref 是 E_ref 输出按作者规则量化得到的 uint8 单通道灰度。原模型内部 F 不传输。

第二阶段从第一阶段的E/D检查点初始化改进版本，在保留原方法任务的基础上加入已有监督；不从头另造生成主干，也不增加分解网络或公共输出头。E_ref/D_ref原版固定归档，改进版编码器E_public生成G1。不能在尚未登记第二阶段训练配置时擅自删掉原恢复目标或固定第二阶段解码器的训练状态；其具体参数更新清单需与新增监督目标一起写入配置。原D0保留用于最终恢复。训练期保留两个版本不是多传一条图像通路；部署只发布最终载体。参考图可在受控训练工作区缓存，但不作为接收端输入。

E_public 输出量化为 U_public，它仍是原方法生成的学习灰度，不是 RGB 转普通灰度。定义：

`Zc = int16(U_ref) - int16(U_public)`

整数范围 [-255,255]，不截断、不转 uint8 后相减。本版序列化采用 little-endian int16，再 zlib 无损压缩；该实现不是最优码率承诺，也不是原论文已有压缩器。9bit 是逐符号固定长度表示所需位数，本版 int16 原始缓冲区为16bit，报告两者不能混淆。

## 2. 完整数字收发

发送：Zc → 无损编码 → KC认证加密 → Cc；外部记录序列化 → KM认证加密 → Cm。将两路密文及基底恢复辅助信息嵌入 U_public，形成 U_tx。实际公开的只有 U_tx 和公开协议配置，不发布 U_ref 或密钥。

接收：仅从实际读回 U_tx 提取 Cc/Cm，并恢复 U_public；两路按独立密钥认证解密。KC 路径解出 Zc 后计算 `U_hat = U_public + Zc`，检查整数范围，再送 `D_ref(U_hat /127.5 -1)`。KM路径独立恢复记录，不需要KC。

目标是 U_hat 与 U_ref 逐像素相同；彩色输出回到原数字基线，不宣称 RGB 无损。原 Decoder 能解码 U_ref 是设计目的，而 U_ref 不公开。U_public/U_tx 是否也能被原 Decoder 或适配攻击者利用，必须独立评价。

## 3. 监督目标和训练顺序

1. **完全按原方法训练得到G0**：E0/D0联合训练，损失、两个训练阶段、灰度外观、量化约束与实际8bit保存验证都对照作者源码。连续输出训练与保存时硬量化分开，不能悄悄加入STE代替原方法。论文/源码不一致处登记，不能混配后称完全原设置。阶段1先采用作者参考的256×256、batch8、90+30阶段；本域数据适配另列，512分辨率或旧batch16不得静默成为原方法设置。完成后保留原E0/D0和G0的绑定记录。当前完整VGG资源、训练器及本域结果未完成，不能用随机网络或协议样本代替。
2. **加入监督训练得到G1**：从阶段1权重开始，保留原方法任务并加入现有监督。原基线归档不覆盖，监督器参数/统计冻结，图像输入梯度保留。先比较G1、G0、普通灰度的身份与医学表现：确认身份下降、医学损失可接受，再进入下一阶段。不是仅把一项医学CE下降当作通过。普通灰度不作为公开生成器。
3. **差值加密、自适应嵌入得到Gpub并再评价**：对同一输入的G0/G1进行统一8bit量化并求有符号Zc。加密后与原有记录路径一起交给自适应写入器W，已有监督约束最终发布图Gpub。比较Gpub与G1、G0和普通灰度，检查嵌入是否破坏已有身份/医学取舍。消息格式、实际码长等属于此阶段的实现检查，不前置取代阶段1/2，也不以固定低位诊断算法代替自适应网络。
4. **训练/完善自适应Encoder/Decoder的完整恢复链**：W为自适应Encoder，R为对应Decoder，区别于原E0/D0。从实际保存并读回的Gpub出发，提取密文并恢复G1；认证解密得到Zc，计算G0_hat=G1_hat+Zc_hat，归一化后送原D0恢复RGB。记录完整消息正确率、G1/G0恢复误差与相对原基线的RGB恢复效果。W/R继续训练后必须回评阶段3的身份/医学指标。

阶段3确定发布图目标和初步嵌入行为，阶段4补齐/强化通信恢复目标；最终W/R需共同满足这两类约束。不能把一个只会生成好看图却忽略载荷的W算作阶段3方法成功，也不能在W/R训练后沿用旧Gpub评价。真实加密不可微，代理训练和真实密文接收的差别必须在阶段3/4显式处理，不默认跨加密反传。

监督目标是公开图身份识别能力降低、医学损失可接受，不要求医学零下降或绝对匿名。已有监督器的语义分离信号与医学输出可用于训练，但当前 PixelSupervisor 工程入口只验证医学 CE 梯度；这不代表身份抑制目标已经接好。身份效果由实际公开图的独立评价判断，不能把医学 CE、q_link幅值或训练损失直接当身份指标。

本方案不预填未知损失权重、训练日程或医学可接受降幅。它们以实验配置登记；先看身份下降与医学代价的配对结果，不自动选冠军。卡数/编号为运行配置，不写入模型；现有多设备验证不等于DDP训练已经实现。

## 4. 对照与验收对象

| 组别 | 目的 |
|---|---|
| 普通灰度 | 身份与医学的常规处理基线；兼作原灰度损失参照 |
| 原论文可逆灰度 | 同域原方法的外观、身份、医学和恢复表现 |
| V4无新增监督 | 隔离通信、表示改动的影响 |
| V4有新增监督 | 在匹配训练/评价条件下检验监督增益与医学代价 |

V4评价最终U_tx；同时诊断U_public，以及任何无需钥匙即可恢复的状态。记录原Decoder直接读取公开图的恢复和身份结果，必要时加入相同预算的适配攻击。容量拒绝样本不能静默从医学/身份汇总删除；报告可承载率、完整消息成功率和失败原因。

在当前完全相同初始化且无监督无其他更新时，U_public=U_ref，差值为0；该组可作协议/通信对照，但不能把与训练后的模型比较完全归因于某一个监督项。监督消融需要匹配训练步数与其他损失，报告实际差值码长和嵌入失真。

## 5. 本轮可运行的是协议诊断，不是完整生成训练

本节代码与合成测试是已发生的独立工程记录。用户纠正顺序后停止将其作为下一步服务器主任务；不继续扩展该载体，保留文件和证据。它没有完成阶段1、2、3或4中的任何一个科研阶段。

`residual_transport.py` 实现：带符号差值、zlib压缩、独立AES-256-GCM两路消息、基底绑定、可逆载体、提取/认证/无损重组。每次生成随机96bit nonce，认证AAD绑定恢复后的公共基底、尺寸、位数及路由；不自行实现密码算法。实验密钥只驻内存、不写日志或配置。持久部署仍需独立密钥和nonce生命周期设计。

密码API依据：[cryptography 44.0.3 AESGCM文档](https://cryptography.io/en/44.0.3/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM)。不修改已有环境依赖。

为了实测基底恢复，诊断载体压缩保存 U_public 的低 b 位，并把这份恢复辅助信息与密文一起写进同一张图的低 b 位；公开高位保持。接收端从图中提取消息及低位恢复信息，恢复完整 U_public。b默认2、可配1–4；最大逐像素改变为2^b−1。公开配置提供b，不依赖发送端掩码。

这里的低位仅是**诊断通信槽位**，不是把颜色/身份定义成低位；Zc仍是两张完整编码灰度的整数差值。该算法不是已完成的自适应神经Writer，不代表最优容量，也不将其固化为最终W/R。

总开销包含帧头、两路nonce/tag、完整差值密文、记录密文和基底辅助信息。不能放下就返回 `capacity_rejected`；不截断、不外置补传。仅支持无损PNG传输，未声称支持JPEG、裁剪、缩放或纠错鲁棒性。

公开恢复辅助信息意味着任何人都可恢复U_public，这是此诊断载体的显式公开状态，监督与攻击评价必须覆盖它。完整差值只通过KC密文传输。

`residual_probe.py` 可跑合成成功/失败样本，或显式传入一对实际8bit单通道PNG。实际PNG必须来自指定的参考模型与公共生成器；脚本不证明其来源。输出只包含发布图和字节/一致性报告，不保存参考图、差值明文或密钥；本轮实验密钥结束后丢弃，不是生产收发入口。

## 6. 命令

在已有依赖环境中，从仓库根目录执行（输出目录必须是新目录）：

```bash
PYTHONPATH=v4:v3:v2:src python -m ccrr_v4.residual_probe \
  --config v4/configs/probe-residual.json --output /absolute/path/new-probe
```

检查真实成对编码图时追加：

```text
--original-png /absolute/path/reference.png --public-png /absolute/path/public.png
```

CPU即可，无GPU选择或训练；服务器使用已有ccrr_v2环境，不安装/升级依赖。真正的原方法同域训练和监督收益尚未由这条命令完成。
