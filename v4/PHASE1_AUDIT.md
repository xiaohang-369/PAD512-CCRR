## 网络与训练输入

作者 `model.py:122–196` 定义独立的编码器/解码器。保留多尺度、残差块、跳接、无 bias 的 E/D 卷积、Normal(0,0.02) 初始化、末端 64→1+tanh 和单通道 D 输入。共 45 个卷积核、7,413,312 个 E/D 参数。既不新建分解网络，也不增加公共输出头。E/D 两段训练都联合更新；预训练 VGG 冻结，但灰度输入的梯度返回 E。

输入/目标均为同一 RGB 图，归一化到 [-1,1]。原 `main.py:17–18` 的 src/dst 都为 target；原 `model.py` 读图只设定 256×256 形状，`set_shape` **不是缩放操作**，仓库没有完整 VOC 裁剪准备脚本。

PAD 适配按用户明确要求：**512×512、全局batch16**。保持原患者划分，使用现有 PAD512 预处理并核验像素 SHA，直接还原相同的uint8像素用于缓存，不再缩放成256。不加裁剪或随机增强，保留原填充；损失和指标覆盖完整512画布。作者示例的256/batch8只作来源记录，不能覆盖本项目的512/batch16要求。当前profile为`author-method-pad512-b16-1`，是原方法在PAD512上的完整两段训练，不是原VOC数据和超参的逐项相同实验。

只用 fit（冻结清单 1,433 图）更新 E/D；val_tune（169 图）监测重建，不按它挑最好模型、不早停。校验划分文件及源文件哈希会读到五角色的证据，但不对 calibration、val_select、test 运行模型或评估性能。

## 损失逐项对照

在归一化空间记 `g=E(x)`、`r=D(g)`、`y=.2989*xR+.5870*xG+.1140*xB`。

| 项 | 固定源码实际运算 | 来源 |
|---|---|---|
| R：恢复 | 所有像素、RGB 通道和 batch 上的 MSE(r,x) | main.py:79–82 |
| P：VGG 对比 | E 输出灰度复制三通道，与 RGB 输入的 VGG **conv4_1 ReLU** 特征做 MSE | main.py:57–63；model.py:208–261 |
| T：局部变化 | `abs(mean_batch(TV(g)/256²) − mean_batch(TV(y)/256²))`；TV 为横纵邻差绝对值之和 | main.py:65–68 |
| B：亮度 | `mean(max(70/127, abs(y−g))) − 70/127` | main.py:70 |
| Q：量化 | 到 `d/127.5−1, d=0…255` 最近网格点的绝对距离均值 | main.py:72–77 |

实际损失：

```text
作者训练段 I，epoch 1–90：
L = 3R + 1e-7 P + 0.5T + B

作者训练段 II，epoch 91–120：
L = 3R + 1e-7 P + 0.1T + B + 10Q
```

512适配的TV分母使用实际像素数`512²`，保持原方法的每像素变化量定义，避免仅因尺寸翻倍把TV项放大四倍。其他损失权重、两段epoch数、量化等级不变。VGG损失分支依然resize到作者要求的224；这不改变E/D的512输入输出。

VGG：先按 TF1 非 half-pixel 双线性坐标 resize 到 224；映射到 [0,255]，RGB→BGR，减 `[103.939,116.779,123.68]`，使用源码的 max-pooling。禁止替换为 torchvision 标准化和任意同名权重。

量化损失不展开 256 份大图，改为查询相邻两个网格点求最小距离，目标和梯度等价；网格仍按作者 NumPy float64 构造后转 float32。已测试全部 256 个网格点与显式展开定义。亮度阈值保留 **70/127**，不自行改为 70/127.5。DDP 下先对 TV 差做全局可微均值，再取绝对值；不能先在每张卡取绝对值。

论文与源码的明确分歧：

| 项 | 论文 | 本次采用的固定代码 |
|---|---|---|
| VGG 层/距离 | §5.2.2：conv4_4、L1 | conv4_1 ReLU、MSE |
| 恢复项权重 | 式3：1 | 3 |
| 后30 epoch灰度项 | 表1整体 ω1 从1降到0.5；α、β不变 | 仅 TV 从0.5变0.1；VGG、亮度权重不变 |
| 亮度阈值 | [0,255] 的70 | [-1,1] 中70/127，折合约70.276灰度级 |

不为“统一”而擅自改写作者代码。本版名称是**固定作者源码的 PAD 同域基线**，不是论文公式另一套实现。

## 训练日程、优化器与数字链

| 配置 | 本次值 |
|---|---|
| 尺寸 / 全局 batch | 512×512 / 16（用户指定） |
| 精度 | FP32，AMP、TF32、梯度累积均关闭 |
| 初始化 | 从零训练原 E/D，不载入作者 VOC 的 E/D 成品 |
| Adam | β1=.9，β2=.999，epsilon=1e-8，无 weight decay |
| 学习率 | 2e-4→2e-6，polynomial power=.9 |
| 步数 | global_step 跨 90/30 共享；进入后30 epoch时重新建立 Adam 一、二阶矩 |
| 学习率衰减跨度 | `floor(N/16) × 120`，按原 main.py:85–96 |
| 每epoch实际更新 | `ceil(N/16)`，按原 main.py:133/176 的 range；连续洗牌流补满 batch |
| 保存 / 选择 | 每10epoch，额外确保90、120；正式基线固定120，不选验证最佳点 |

对冻结 fit=1,433：每 epoch 90 步，前90epoch为8,100步，后30epoch为2,700步，共10,800步；LR在第10,680步到达终值，最后120步保持终值。保留源码ceil更新/floor衰减规则，不使用drop_last。

TF1 Adam：`lr_t=lr*sqrt(1−β2^t)/(1−β1^t)`，`w -= lr_t*m/(sqrt(v)+epsilon)`。这里 epsilon 加在未偏差校正的 v 根号后，与直接使用默认 PyTorch Adam 不完全一样，因此单独实现并用独立 NumPy 计算核对。TF1 的 beta power 累乘与本实现的幂计算、随机队列顺序、底层卷积归约仍可能产生浮点差异；没有逐位复现声明。

训练前向仍是 `x→E→g(连续)→D→r`；Q 是梯度惩罚，**不在训练 E/D 之间偷偷放硬取整或 STE**。每 epoch 的验证另外执行：

```text
g → floor((g+1)*127.5+0.5) → 单通道8bit PNG字节
  → 实际PNG解码 → 除127.5再减1 → 原D → 恢复RGB
```

报告分别记录连续链与 PNG 链的 RGB MSE、按图均值 PSNR，另列作者风格的各颜色通道 PSNR 均值；量化灰度 MAE 使用0–255单位。PSNR零误差按100dB上限记。PNG在内存文件中真实编码/解码，不用浮点旁路替代。这里不会声称 RGB 数学上无损复原。

## 工程变化与证据边界

工程变化仅为框架适配、数据角色与哈希绑定、多卡全局 batch、不可覆盖的运行目录、保留历史检查点、日志与数字链评估；不改变原 E/D 任务。原作者仅保留最近检查点，这里保留历次文件便于追溯。显式 resume 从指定 epoch 检查点写入**新目录**，保持数据流位置/global_step/Adam 状态；从90进入91时仍重置第二个Adam。完成120即退出。每次checkpoint另保存固定val_tune前4图的5列预览（RGB、普通灰度、G0、PNG后恢复RGB、4倍绝对误差），只留在私有服务器run内，便于人工审核。

本地验证包括：原模型源码 NumPy 算子对照、损失/量化、VGG预处理与梯度、Adam、连续批次、多进程 TV 全局归约、90/30控制流与90断点恢复。本次真实已核对VGG＋完整E/D在合成512图上（本地检查batch1，正式全局batch16需服务器预检），两段loss均可反向传播，零参数更新，PNG链可读回。旧256缓存被明确拒绝。这些不是 PAD 训练结果，也不是 GPU/NCCL 或 TF1.6 原生运行证明。

服务器正式运行前需要返回：安装通过、数据准备通过、所选设备上的零更新 preflight 通过。全部90＋30训练完成后，还要审核曲线、量化前后恢复质量和样例，才能将 E0/D0/G0 登记为后续基线；退出码或低loss本身不代表科学验收。不得自动进入 V4 第二阶段。
