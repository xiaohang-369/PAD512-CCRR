# H100 部署与 A 阶段操作指南

本轮没有连接 H100、下载/安装资源或启动正式训练。以下由用户在服务器分步执行，每一步检查输出后再继续；不要直接运行 `--stage all`。当前本地仓库尚未配置 GitHub 远端，推送须先确认 URL、分支和文件清单。

## 1. 代码与资源

确认推送后，在服务器克隆已确认的仓库并检出 `fix/pad512-v1.1-stage-a-admission`，记录 `git rev-parse HEAD`。数据、权重、官方 PanDerm 源码与私有实验目录分别放到源码目录之外。完整复制冻结数据目录（含 `raw/metadata.csv`、`study_v1`、`protocol_audit_20261009` 和实际源图）；不要只拷 fit 图像而丢失核验证据。

使用用户自己准备的 Python 3.11 环境及项目固定依赖，CUDA 构建适配服务器驱动。安装命令须由用户另行确认；此指南不自动安装。先执行：

```bash
nvidia-smi
python -m pip check
python -m ccrr.cli inspect
```

预期：可用 H100；`pip check` 无依赖冲突；torch=2.6.0、torchvision=0.21.0（允许 CUDA build 后缀），其余版本与 pyproject.toml/preflight 相符。若发现 CPU-only torch、非 H100 或依赖不一致，先处理环境，不改门禁。

将 `configs/stage_a_h100.yaml` 复制到源码外，例如 `/srv/ccrr/a.yaml`，逐项修改真实绝对路径。该模板保存三个已核验权重的完整 SHA，PanDerm 固定 commit/source SHA；J 的权重仍为空。不要改 seed/预算/512/batch/阈值。`interface_reports` 的 SHA 暂为空是有意的，必须完成服务器实测后再绑定。

## 2. 逐模型真实接口

先固定环境，所有后续 Python 进程保持一致：

```bash
export CUBLAS_WORKSPACE_CONFIG=:4096:8
export CUDA_VISIBLE_DEVICES=0
mkdir -p /srv/ccrr/checks
```

逐条执行，不并行加载模型。路径若调整，命令和 YAML 一起调整。

```bash
python scripts/check_teacher_interface.py --device cuda --model efficientnet_b0 \
  --weights /srv/ccrr/resources/weights/efficientnet_b0_rwightman-7f5810bc.pth \
  --sha256 7f5810bc96def8f7552d5b7e68d53c4786f81167d28291b21c0d90e1fca14934 \
  --out /srv/ccrr/checks/efficientnet_b0.json
```

确认四个 `INTERFACE_PASS`、`passed=true`、无缺键/shape 错误，再执行：

```bash
python scripts/check_teacher_interface.py --device cuda --model resnet50 \
  --weights /srv/ccrr/resources/weights/resnet50-11ad3fa6.pth \
  --sha256 11ad3fa62ca79e40addfd354a8ec4b7c75143b3038b8d2a807fbc68deab379ca \
  --out /srv/ccrr/checks/resnet50.json
```

确认通过后再执行 PanDerm：

```bash
python scripts/check_teacher_interface.py --device cuda --model panderm \
  --weights /srv/ccrr/resources/weights/panderm_bb_data6_checkpoint-499.pth \
  --sha256 be1e0fb108b3bc58721cb5195f136c948160799438f222acf1fd142230ac1ff1 \
  --source /srv/ccrr/PAD-UFES-20/protocol_audit_20261009/official_sources/panderm_classification_models_modeling_finetune.py \
  --out /srv/ccrr/checks/panderm.json
```

PanDerm 额外须 `official_norm_patch_tokens_exact=true`、norm 后去 CLS 的 14×14×768 网格正确。`meshgrid` indexing 提醒不改变接口；其他异常不要通过放宽 strict loading 解决。CUDA OOM、非有限梯度、确定性算子错误须保留报告并停止。

三个真实报告均通过后，只给 YAML 写入其文件摘要（不改变资源或报告内容）：

```bash
python - <<'PY'
from pathlib import Path
import hashlib, json, yaml
p = Path('/srv/ccrr/a.yaml')
c = yaml.safe_load(p.read_text())
for name, e in c['interface_reports'].items():
    f = Path(e['path'])
    r = json.loads(f.read_text())
    assert r['passed'] and r['model'] == name and r['device'] == 'cuda'
    assert r['sha256'] == c['weights'][name]['sha256']
    e['sha256'] = hashlib.sha256(f.read_bytes()).hexdigest()
p.write_text(yaml.safe_dump(c, sort_keys=False))
print('已绑定服务器真实接口报告；尚未启动训练。')
PY
```

## 3. 工程与资源验收

```bash
python -m pytest -q
python -m ccrr.cli preflight --config /srv/ccrr/a.yaml --stage A
```

预期：全部工程测试通过。服务器若未提供已核验的原生 CompressAI 参考库，只有该可选互操作项可以跳过；不能把 Mac 的 `.so` 复制到 Linux 当参考。当前 Mac 完整结果为 169 passed（包含原生参考）。CUDA 版本的 A 恢复对照须另行执行；CPU pytest 不等于 CUDA 位级一致：

```bash
CCRR_TEST_DEVICE=cuda python -m pytest tests/test_stage_a_resume.py tests/test_stage_a_training_loops.py -q
```

该命令使用小型合成网络执行生产恢复/训练循环，不加载新权重、不开展正式训练；CUDA 不可用或确定性失败时应失败。

preflight 必须退出 0、`ready_for_stage=true`、`missing=[]`。全量数据检查会读取 2,264 张图，耗时依赖存储。报摘要错时检查传输/文件版本，不重新生成“匹配”摘要；known overlap 拒绝不能通过改成 unknown 隐藏事实。

逐个运行合成完整有效 batch 资源检查：

```bash
python scripts/check_stage_a_host.py --config /srv/ccrr/a.yaml \
  --model efficientnet_b0 --out /srv/ccrr/checks/clinical-batch16.json
python scripts/check_stage_a_host.py --config /srv/ccrr/a.yaml \
  --model resnet50 --out /srv/ccrr/checks/reid-pairs16.json
```

预期：有限参数梯度、记录 peak allocated/reserved 和时间；无 dataset 读取、零 optimizer updates。Clinical 为 16 图 × 双域，ReID 为 16 对 × 两端，FP32、冻结 BN running statistics。检查空闲显存能容纳报告中的 AdamW 状态额外估算、正式 Experiment 中其他驻留模块和保存开销；这些额外占用仍需正式服务器准入实测，不能仅凭此单模型检查声称整段训练资源已通过。

磁盘应能保存全部规定端点及 latest（含 optimizer 和最佳模型副本）。逐 seed 使用独立输出目录；不要让两个进程同时写同一个目录。先保留以上输出，确认 CUDA 重放检查后，再由用户启动正式训练。

## 4. 用户确认资源后，正式 A 的顺序与停止条件

```bash
python -m ccrr.cli train --config /srv/ccrr/a.yaml --stage A
```

实际固定顺序：Clinical 双域 5,000 → RGB-only 5,000 → gray-only 5,000 → Clinical 门禁 → 冻结 PanDerm patch probe 2,000 → MFM 门禁 → ReID 10,000 → P1/P2 独立报告、P1 门禁 → 私有冻结记录。阶段没有通过则停止，不用增大预算/降低阈值补成成功，也不启动 B。

训练完成后检查 `acceptance.json`、`validation/*-selected.json`、`validation/reid-capability.json`、`teacher_freeze_record.json` 和 `checkpoints/endpoints/`。A 是监督工具准入，不能宣称公共系统最终效用/隐私通过。

保持三个预登记 seed（20261008、20261009、20261010），各自使用独立配置/output，分别执行相同预算。报告每 seed 的结果和患者区间，再汇总均值/范围；不合并患者×seed，不选最好 seed，不从 test 选点。当前代码一次执行一个 seed，不伪造已完成多 seed 研究。

## 5. 中断恢复

同一代码、资源、seed、设备拓扑/软件环境和输出目录下：

```bash
python -m ccrr.cli train --config /srv/ccrr/a.yaml --stage A --resume
```

恢复 `.last.pt` 最近持久 optimizer 边界，默认至多重做 99 步；不从 `clinical.pt` 等 selected-only 文件恢复优化器。已经跑满子阶段不重复更新，仍执行报告/门禁。格式 v1、缺前序状态、错代码/环境/预算会拒绝；不要手动改 step 或复制一个最佳 checkpoint 当 latest。

Mac 三个生产循环的合成优化器恢复对照已通过，CUDA 实测仍待服务器。正式运行前执行第 3 节 `CCRR_TEST_DEVICE=cuda` 命令，比较参数、AdamW moments、scheduler、RNG、step、选点和采样记录；失败先排查确定性/版本，不能靠放宽数学门槛忽略差异。
