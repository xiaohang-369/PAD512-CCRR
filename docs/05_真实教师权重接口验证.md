## 实物发现并修复的 D24 导入问题

初次真实PanDerm加载失败：`KeyError: 'ccrr_official_panderm'`。文件可读、SHA和state_dict均正常；错误发生在官方源码的 `@register_model`，还未进入权重加载。原工程调用 `exec_module` 前没有登记 `sys.modules`，而timm按函数的模块名查找模块。

`teachers/adapters.py:load_panderm_source` 现在先核验源码摘要，以完整摘要生成模块名，登记后执行；同摘要模块复用，失败则移除部分模块并原样抛错。`PanDerm.__init__` 调用这一入口。未放宽权重检查、未修改官方源码、未改变任何网络参数结构或checkpoint格式。

`tests/test_teacher_source_import.py` 三项测试分别覆盖执行前注册、导入失败清理及摘要不符时不执行源码。这里的临时源码只用于测试Python导入机制，不作为真实PanDerm通过证据。

## 前向和梯度实际结果

每模型均使用512×512合成RGB及其规定标准灰度，分别检查完整画布和非方形有效矩形 `(0,64,512,384)`。这不是医学样本能力评价。

- EfficientNet：六分类logits `[1,6]`，空间特征 `[1,1280,16,16]`。
- ResNet：embedding `[1,2048]`，L2范数约1，空间特征 `[1,2048,16,16]`；新增863类患者头仅检查接口。
- PanDerm：由工程224适配得到 `[1,768,14,14]`，覆盖率 `[1,1,14,14]`。通过官方 `forward_features` 的最后norm层hook，逐位核对196个patch tokens及其排列；CLS正确排除，未把官方默认CLS向量当作空间特征。
- 全部输入/输出和梯度有限，输入梯度非零；冻结参数无grad，参数及buffer指纹前后不变。
- PanDerm官方源码的 `torch.meshgrid` 发出未来需要显式indexing的提示，当前版本测试通过；未为消除提示修改固定源码。

三份旧单模型记录与初次失败记录保存在源码外 `CCRR-experiments/teacher-interface-checks-20261010/`。新增可复现检查器：[check_teacher_interface.py](../scripts/check_teacher_interface.py)，只读用户提供的本地资源，不含下载或训练代码。

```bash
python scripts/check_teacher_interface.py \
  --model panderm \
  --weights /controlled/weights/panderm_bb_data6_checkpoint-499.pth \
  --sha256 be1e0fb108b3bc58721cb5195f136c948160799438f222acf1fd142230ac1ff1 \
  --source /controlled/sources/modeling_finetune.py \
  --out /controlled/checks/panderm.json
```

TorchVision模型使用同一检查器，`--model`取 `efficientnet_b0` 或 `resnet50`，省略 `--source`，提供上表对应文件和摘要。输出包含源码指纹、键/shape核对、四组前向/梯度和明确的能力未验证标志。一次只执行一个模型。

完整工程回归：**136 passed，0 failed，0 skipped，0 xfailed，10.36秒**，启用已有原生编码参照；ruff F检查通过。原固定字节、独立凭证、512 INN/通信梯度、CLI与checkpoint测试均保留。
