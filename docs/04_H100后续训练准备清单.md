# PAD512-CCRR-v1.1 H100 后续训练准备清单

本清单是本次架构审查的交付物，不表示已经授权或执行正式训练。依据最终设计稿，不提出新的网络、研究目标或协议。

## 1. 能否下载权重后只填路径就开始？

**不能作此承诺。** 目前有完整训练循环和严格资源加载入口，但同时存在三类前置工作：

| 类别 | 现状 | 开始相关阶段前必须完成 |
|---|---|---|
| 路径/环境配置 | 默认权重为空；本机是CPU环境 | H100环境锁、外部数据/输出路径、官方文件及SHA-256、固定PanDerm源码与依赖 |
| 模型适配实物核验 | torchvision适配器、PanDerm Base官方接口存在；没有真实权重加载证据 | 严格验证checkpoint容器/键/shape、空间输出、冻结与输入梯度；有不匹配时只作格式适配，不能换网络或静默漏载主干 |
| 已知实现差距 | 设计冲突D01–D24见验证报告 | 逐项按最终稿修复/补证，尤其D03/D04/D05/D06/D07/D09/D10/D11/D16；通过专门复核后才能把相应阶段称为正式协议运行 |

若修复必须改变最终稿的网络结构、字段、目标、阈值或数据成员，应停止该项并提交冲突说明。现有错误本身不构成修改研究方法的授权。对已经写明的最终稿要求可以规划落实，但本轮未把它们混入结构迁移。

## 5. 每轮标定成本与验收

最终稿固定calibration154图，每图最多4区域，每k=0…4：工作T64最多197,120张probe载体；最终T256最多788,480张，另加val_tune阈值/外部标定、风险图和整图检查。风险图每图最多2048次Clinical前向。这是预登记计算量，不是本轮实测时间。

不能将本机约2秒的随机512 smoke当作H100正式耗时估算。首次H100先记录每组件前向/反向、32端点配对额外开销、峰值显存和probe吞吐；只通过等价批处理/冻结特征缓存提高效率，不减少T、区域、负载、整图次数或研究有效batch。发生OOM时保存诊断，不改512或改结构使运行“通过”。

## 6. 最终验收必须分别给出的结论

1. **数字正确性**：一次实际Gpub盲提取，认证C/M后整数latent及26字段与发送对象完全一致；未授权/错钥/篡改不放行明文。RGB只按近似高保真目标评价。
2. **容量/通信**：全合规输入发布及C、M、双成功均≥95%；每病种发布及双成功≥90%；已发布中C/M/双完整恢复各≥99%。容量拒绝和认证失败保留各自分母。
3. **RGB画质**：均值PSNR≥30、SSIM≥.95；至少90%有效结果同时≥28/.90；给分位数、病种和区间。
4. **临床**：独立RGB评价器先≥.75；公共相对同发布子集RGB AUROC下降≤.03、F1≤.05；恢复相对同有效恢复子集RGB AUROC下降≤.02；按最终稿配对区间决定是否有统计支持。
5. **隐私**：P1/P2各方向最强A†≤.60且相对灰度优势减少≥50%；先满足原图/灰度攻击有效性。P1/P2/P3 Rank-1按固定机会率与相同查询/图库比较；P3原图库338不被悄悄缩减。视觉授权收益须对预登记无钥重建攻击逐个给出配对差值和区间。
6. **统计与复现**：三seed分别列“通过/未通过/点达标但证据不足/未评”；患者聚类和患者全成功Wilson分开。配对、增强和重复nonce不是新增独立患者；零失败bootstrap退化不能当作可靠性证明。
